# 갈래 후보 자동 배치 — 설계 문서

- 작성일: 2026-09-28
- 상태: 검토 중
- 배경: 갈래별 후보(현대시 132편·고전운문 32편)가 모였고, 이제 권별 배치를 논의해야 한다. 2026-09-28에 Claude가 현대시 132편을 기획안 기준으로 수동 배치한 엑셀(`회의/[0928] 2차 회의/현대시_권별 배치안_20260928.xlsx`)을 만들었고, 사용자가 같은 기준을 대시보드 기능으로 넣기를 요청함.
- 단계 이름: 5단계(phase5). 브랜치 `phase5`, 완료 태그 `phase5-done`.

## 0. 결정 요약 (사용자 확정)

| 항목 | 결정 |
|---|---|
| 콘셉트 판단 | **규칙 + 콘셉트 태그**. LLM API 호출 없음 — 후보마다 "어울리는 권" 태그를 사람이 편집, 현대시 132편 태그는 Claude가 미리 채움 |

| 반영 방식 | **미리보기 → 조정 → 적용**. 이미 배치된 작품은 건드리지 않음 |
| 부 배정 | 현대시·고전운문 → 1부, 현대소설 → 2부, 현대수필·극 → 3부, **고전산문 → 부 미배정**(2·3부 어느 쪽도 가능하므로 사람이 정함) |

v2 설계 §12의 "AI 없음" 범위 제외와 충돌하지 않는다 — 이 기능은 규칙 기반 계산이며 외부 AI 호출이 없다.

## 1. 데이터 모델 (`supabase/phase5.sql`, Studio에서 1회 실행)

기존 데이터는 바뀌지 않고 칸·테이블만 추가된다.

### 1.1 `volumes.curricula text[] not null default '{}'`

권이 대응하는 교육과정기. 값은 작품 DB 시트의 `교육과정` 표기와 동일('1차'…'7차', '2007개정', '2009개정', '2015개정', '2022개정').

SQL 실행 시 기획안(시리즈 구성)대로 채운다:

| 권 | curricula |
|---|---|
| 1 | {1차,2차,3차} |
| 2 | {4차} |
| 3 | {5차} |
| 4 | {6차} |
| 5 | {7차} |
| 6 | {2007개정,2009개정} |
| 7 | {2015개정} |
| 8 | {2022개정} |

(`update volumes set curricula = … where number = N` — 해당 번호의 권이 없으면 영향 0행, 오류 아님.)

권 목록의 권 수정 폼에 교육과정 다중 선택(`MultiSelectDropdown` 재사용)을 추가한다. `curricula`가 빈 권은 자동 배치 대상에서 빠지고 화면에 안내된다.

### 1.2 `genre_picks.concept_volume_ids uuid[] not null default '{}'`

후보별 "어울리는 권"(콘셉트 태그). 권 번호가 아닌 권 ID로 저장해 권 번호가 바뀌어도 유지된다. 권이 삭제되면 남은 ID는 계산 시 무시한다(참조 무결성 강제 안 함 — 배열 컬럼).

시드: 현대시 132편 태그를 `src/tests/fixtures/modernPoetry132.json`(작품명·작가·수록 교육과정·태그 권 번호)에 두고, 이 파일에서 시드 SQL을 생성한다(`scripts/gen-phase5-seed.mjs`). SQL은 `works_registry`의 `title`·`author_base`로 후보를 찾아 권 번호 → 권 ID로 변환해 채우고, 마지막에 **매칭되지 않은 작품 수**를 select로 출력한다.

### 1.3 `placement_batches` (신규)

| 칸 | 타입 | 설명 |
|---|---|---|
| id | uuid pk | |
| genre | text not null | 갈래 버킷(현대시 등) |
| item_count | int not null default 0 | 실제 추가된 편수 |
| created_part_ids | uuid[] not null default '{}' | 이 적용으로 새로 만든 부 |
| created_by | uuid | 트리거로 기록(기존 `set_registry_created_by` 재사용) |
| created_at | timestamptz default now() | |
| undone_at | timestamptz | 되돌린 시각(null = 유효) |
| undone_by | uuid | |

RLS: 기존과 동일하게 `is_member()` 전원 허용.

### 1.4 `volume_works.placement_batch_id uuid references placement_batches(id) on delete set null`

자동 배치로 들어간 행에만 값이 있다. 손으로 추가한 행은 null.

### 1.5 저장하지 않고 계산하는 값

- 작품의 수록 교육과정: 작품 DB 시트(`useWorksData`)에서 registry 키(별칭 포함)로 실시간 조회. 시트에서 못 찾으면 `genre_picks.work_snapshot.curriculum`으로 대체.
- 첫 수록 시기: 수록 교육과정 중 `curriculumRank`가 가장 앞선 값.

## 2. 배치 계산 — `src/board/autoPlace.js` (순수 모듈)

### 2.1 입력

```js
autoPlace({
  works,        // [{ workId, title, author, curricula: string[], conceptVolumeIds: string[] }] — 배치 대상(미배치 후보)
  volumes,      // [{ id, number, curricula: string[] }] — curricula 빈 권은 호출 전에 제외
  existing,     // [{ volumeId, workId, author, bucket, selection_status }] — 이미 배치된 행 전체(모든 갈래)
  bucket,       // '현대시' 등 — 편수 균형 계산 범위
})
// → { placements: [{ workId, volumeId, reasons: ['debut'|'concept'|'balance'], warnings: ['authorDup'] }],
//     unplaceable: [{ workId, reason: 'noEligibleVolume'|'authorLimit' }] }
```

### 2.2 대상

- 고른 갈래의 후보 중 **미배치**(어느 권에도 없거나 모두 `excluded`) 작품. 기준은 검색 패널 '미배치만' 토글과 동일.
- 작품이 `excluded` 상태로 들어가 있는 권에는 다시 제안하지 않는다.

### 2.3 점수 (작품 w를 권 v에 둘 때)

| 조건 | 점수 |
|---|---|
| w의 수록 교육과정 ∩ v.curricula = ∅ | **배치 불가**(후보 권에서 제외) |
| 기본 | +10 |
| v.curricula에 w의 첫 수록 교육과정 포함 (`debut`) | +3 |
| v.id ∈ w.conceptVolumeIds (`concept`) | +4 |
| v에 같은 작가가 이미 1편 (기존 행 + 제안 포함, **모든 갈래**) | −15, **한 권 같은 작가 최대 2편**(하드 제약) |
| v의 같은 갈래 편수(기존+제안)가 [평균−3, 평균+3] 밖 | 벗어난 1편당 −10 |

평균 = (같은 갈래 기존 편수 합 + 대상 편수) ÷ 대상 권 수. 상수는 모듈 상단 `WEIGHTS`로 모은다.

가중치 조정 기록(2026-09-28, 계획 작성 중 132편 시제품 검증): 최초 −8/−5에서는 피할 수 있는 작가 중복(2권 김현승)이 남고 2권이 10편으로 줄어, −15/−10으로 올림 → 132편 결과: debut 85·concept 113·작가 중복 2곳(백석·정지용)·권별 13~19편.

### 2.4 알고리즘

1. 후보 권 수가 적은 작품부터(동률은 작품명 가나다순) 현재 상태에서 점수가 가장 높은 권에 배정. 둘 곳이 없으면(모든 후보 권이 작가 한도 초과) `unplaceable`.
2. 개선 반복: 전체 점수가 오르는 한 (a) 작품 하나를 다른 후보 권으로 이동, (b) 서로 다른 권의 두 작품 맞교환을 시도하고 이득이 있으면 적용. 순회 순서 고정, 최대 50회 전체 순회로 상한.
3. 결정적: 같은 입력이면 같은 결과(난수 없음).
4. `reasons`: debut/concept 해당 여부, 둘 다 아니면 `balance`. `warnings`: 같은 권 같은 작가 2편이면 `authorDup`.

### 2.5 품질 기준 (테스트로 고정)

`modernPoetry132.json` + 1~8권 기획안 curricula, 기존 배치 없음 조건에서:
- 132편 전원 배치(`unplaceable` 0)
- 수록 이력 없는 권 배치 0
- 작가 중복(2편인 권·작가 쌍) ≤ 2 — 백석(6편/가능 권 5)·정지용(7편/가능 권 6)은 불가피
- `debut` 배치 수 ≥ 85 (2026-09-28 엑셀 배치안의 debut 수. 파이썬 정수계획 최적해는 86이었고 김현승 중복 해소로 1편 이동)
- 콘셉트 태그 적중(`concept`) 배치 수 ≥ 110 (엑셀 배치안 기준 115에서 목적함수 차이 여유 5)

## 3. 화면

### 3.1 진입

- 권 목록(`/volumes`) 상단에 **'자동 배치'** 버튼 → `/auto-place`.
- 페이지 상단: 갈래 알약 버튼(갈래별 후보 탭과 같은 모양), "미배치 후보 N편 · 대상 권 M개", `curricula` 빈 권 안내.
- 갈래를 고르면 즉시 계산.

### 3.2 배치안 격자

- 권별 비교(`/compare`)처럼 권 = 열(4열 격자, 좁은 화면에서 줄바꿈).
- 열 머리: 권 번호·제목, 교육과정기, 편수 "기존 n + 신규 m".
- 기존 배치(같은 갈래)는 회색 읽기 전용 행.
- 신규 제안은 카드: 작품명·작가, 근거 뱃지(첫 수록 / 콘셉트 / 균형), 경고 뱃지(작가 중복).
- 카드마다 **권 이동** select(모든 대상 권, 수록 이력 없는 권은 "⚠ 수록 이력 없음" 표기)와 **빼기** 버튼.
- 조정 시 편수·작가 중복 경고 즉시 재계산(점수 재최적화는 하지 않음 — 사람의 조정을 존중).
- 권 안 정렬: 첫 수록 시기 → 작품명.

### 3.3 보류함

- 격자 아래. `unplaceable` 작품(이유 표시)과 사람이 뺀 작품. 권 select로 다시 넣을 수 있다.
- **다시 계산**: 처음 제안안으로 되돌림. 수동 조정이 있으면 확인을 묻는다.

### 3.4 엑셀로 저장

2026-09-28 배치안 엑셀과 같은 구성(한눈에 보기 / 권별 배치안 / 배치 기준), `xlsx-js-style`, 기존 `exportPicks.js` 관례(연번·파랑 머리행) 따름. 파일명 `{갈래}_권별 배치안_{YYYYMMDD}.xlsx`. 현재 화면 상태(조정 반영)를 저장.

### 3.5 적용

1. 확인 창: 갈래와 권별 편수 요약("현대시 132편 → 1권 15 · 2권 13 · …"), 새로 만들 부 목록("3권에 '1부'가 없어 새로 만듭니다").
2. 최신 `volume_works`를 다시 읽어 그사이 배치된(비`excluded`) 작품·해당 권에서 `excluded`된 작품은 건너뛴다.
3. `placement_batches` 행을 먼저 만든다.
4. 부 확보: 버킷의 부 번호(1/2/3, 고전산문은 null)가 그 권에 없으면 `createPart`로 만들고 `created_part_ids`에 기록. 부 제목은 '시'/'소설'/'수필·극'.
5. 작품을 한 편씩 insert(`work_id`는 후보의 것, `work_snapshot`은 후보 snapshot, `selection_status` 기본 candidate, `part_id`, `placement_batch_id`, `sort_order`는 그 권 기존 최댓값 뒤로). 실패해도 계속하고 실패 목록 수집. unique(volume_id, work_id) 충돌은 "이미 있음"으로 건너뜀.
6. `item_count` 갱신. 결과 요약(추가 n, 건너뜀 k, 실패 f) + 권별 비교 링크.

### 3.6 적용 기록과 일괄 되돌리기

- 페이지 하단 **적용 기록**: 갈래, 편수, 적용자, 시각, 상태(유효/되돌림). 유효한 묶음에 **되돌리기** 버튼(전원).
- 되돌리기:
  1. 그 묶음의 `volume_works`를 읽는다.
  2. **손댄 작품은 남긴다**: `selection_status ≠ 'candidate'`이거나 `work_tasks`·`work_comments`·`files`가 하나라도 있는 행. (삭제 시 cascade로 딸린 업무·의견·자료가 지워지므로 타인의 작업 보호.)
  3. 나머지를 삭제.
  4. `created_part_ids` 중 비어 있게 된 부를 삭제.
  5. `undone_at`·`undone_by` 기록.
  6. 요약: "28편을 뺐습니다. 4편은 남겼습니다: 〈서시〉(2권 확정), …"
- 판정 로직은 순수 함수 `splitUndoable(rows, tasks, comments, files)`로 분리.
- 추가·삭제 내역은 기존 `activity_log` 트리거가 기록.

### 3.7 갈래별 후보 탭 — 콘셉트 태그

각 후보 행에 "어울리는 권" 칩(`7권 8권`). 클릭 시 권 체크 목록 팝오버(`PartControls`의 팝오버 관례 참고) → 저장 시 `genre_picks.concept_volume_ids` update.

## 4. 오류 처리

| 상황 | 처리 |
|---|---|
| 작품 DB 시트 로드 실패 | 후보 snapshot의 교육과정으로 계산, 상단에 "시트 연결 실패로 저장된 정보로 계산했습니다" |
| 시트에서 작품 못 찾음(개명 등) | 해당 작품만 snapshot 교육과정 사용 |
| 맞는 권 없음 / 작가 한도 | 보류함 + 이유 |
| 적용·되돌리기 도중 끊김 | 묶음 행을 먼저 만들므로 들어간 만큼은 묶음에 연결되어 되돌리기 가능. 실패 목록 표시 |
| phase5.sql 미실행(컬럼·테이블 없음) | 자동 배치 페이지에 "DB 업데이트(phase5.sql) 실행이 필요합니다". 다른 화면 영향 없음 — 기존 쿼리는 새 컬럼을 요구하지 않게 작성 |
| 태그의 권 ID가 삭제된 권 | 무시 |

## 6. 진행 순서

1. 이 설계 문서 커밋 → 사용자 검토.
2. writing-plans로 구현 계획서 → 서브에이전트 방식으로 `phase5` 브랜치 구현(구현 → 리뷰 → 수정 → 최종 리뷰 → 병합).
