# 문학 단행본 시리즈 개발 업무 대시보드 — 설계 문서

- 작성일: 2026-08-12
- 상태: 승인됨 (사용자 확정)
- 관련 프로젝트: [literature-db](../../../../literature-db) (기존 교과서 문학 단행본 DB 사이트)

## 1. 목적

편집부와 편찬위원단(합계 10명 내외, 향후 15명 정도까지)이 함께 사용하는 문학 단행본 시리즈 개발 업무 대시보드를 만든다. 연락처·일정·자료 공유 같은 협업 기본 기능과, 기존 교과서 문학 단행본 DB와 연동된 **권별 작품 목록 실시간 편집**이 핵심이다.

## 2. 확정된 요구 조건

| 항목 | 결정 |
|---|---|
| 사용자 규모 | 편집부 5명 + 편찬위원 5명. 외부인 포함. 15명 내외까지 확장 고려 |
| 로그인 | 이메일 초대 링크(매직 링크). 비밀번호 없음 |
| 편집 권한 | 전원 전체 편집 가능. 대신 모든 변경에 수정자·수정 시각 기록 |
| 파일 공유 | 직접 업로드(Supabase Storage)와 외부 링크(구글 드라이브 등) 첨부 병행 |
| 배포 | GitHub Pages (기존 literature-db와 동일). 필요시 Vercel 전환 가능 |
| 비용 | Supabase 무료 플랜으로 시작. 저장 용량 1GB 초과 시 링크 첨부 위주로 전환하거나 유료 검토 |

## 3. 아키텍처

```
편집부·위원 (10~15명)
    │  이메일 매직 링크 로그인
    ▼
series-dashboard (React + Vite SPA, GitHub Pages)
    ├─ 홈: 최근 활동 피드, 다가오는 마감
    ├─ 권별 작품 목록: 작품 검색 → 권에 추가/순서 조정/상태 변경 (실시간 동기화)
    ├─ 일정: 시리즈 마일스톤 + 권별 마감 (캘린더/목록 뷰)
    ├─ 자료실: 권별 폴더, 파일 업로드 + 링크 첨부
    └─ 연락처: 구성원 명부
    ▼
Supabase (무료 플랜)
    ├─ Auth: 매직 링크, 초대 기반
    ├─ Postgres: volumes, volume_works, schedules, files, members, activity_log
    ├─ Storage: 업로드 파일
    └─ Realtime: volume_works 등 변경 구독
    ▲
기존 works 구글 시트 (게시 CSV) ─ 작품 원본 데이터. 읽기 전용으로 유지
```

### 원칙

- **작품 원본 데이터의 원천은 지금처럼 구글 시트.** 대시보드는 시트를 읽기만 하고, "어떤 작품을 몇 권에 넣는가"라는 선정 정보만 Supabase에 새로 저장한다. 기존 워크플로(시트 관리, literature-db 사이트)를 깨지 않는다.
- 기존 literature-db의 `parseCSV`, 필터 로직, 검색 UI 패턴을 재사용한다.
- 데이터 접근 제어는 Supabase RLS(Row Level Security)로 강제한다: 로그인한 구성원만 읽기/쓰기 가능. 프런트엔드 코드가 공개 저장소에 있어도 데이터는 보호된다.

## 4. 기술 스택

- React 19 + Vite + Tailwind CSS 4 (literature-db와 동일 계열, 유지보수 일관성)
- `@supabase/supabase-js` — 인증, DB, 스토리지, 실시간
- Vitest + Testing Library — 기존 프로젝트와 동일한 테스트 구성
- GitHub Actions → GitHub Pages 배포 (기존 deploy.yml 패턴 재사용)

## 5. 데이터 모델

### members (구성원)

| 컬럼 | 설명 |
|---|---|
| id | Supabase auth user id 참조 |
| name | 이름 |
| affiliation | 소속 (예: 편집부, ○○고등학교) |
| role | `editor`(편집부) / `committee`(편찬위원) |
| assigned_volumes | 담당 권 (표시용, 권한 제한 없음) |
| phone, email | 연락처 |

### volumes (권)

| 컬럼 | 설명 |
|---|---|
| id, number | 권 번호 |
| title | 권 주제명 (예: 다양한 삶의 모습) |
| status | `기획` / `선정중` / `확정` / `제작중` / `완료` |
| editor_id | 담당 편집자 |
| note | 메모 |

### volume_works (권별 수록 작품) — 핵심 테이블

| 컬럼 | 설명 |
|---|---|
| id | |
| volume_id | 권 참조 |
| work_key | 작품 식별자 (시트 데이터의 작품명+작가 조합 키) |
| work_snapshot | 추가 시점의 작품 정보 JSON (작품명, 작가, 갈래, 교육과정 등) — 시트가 바뀌어도 목록이 깨지지 않도록 스냅숏 보관 |
| sort_order | 수록 순서 |
| status | `후보` / `확정` / `제외` |
| note | 선정 이유·의견 메모 |
| created_by, updated_by, created_at, updated_at | 이력 |

### schedules (일정)

| 컬럼 | 설명 |
|---|---|
| id, title | 일정명 (예: 3권 원고 마감) |
| volume_id | 권 참조 (null이면 시리즈 공통) |
| due_date | 마감일 |
| assignee_id | 담당자 |
| done | 완료 여부 |

### files (자료)

| 컬럼 | 설명 |
|---|---|
| id, name | 파일명/자료명 |
| volume_id | 권 참조 (null이면 공통 자료실) |
| kind | `upload` / `link` |
| storage_path | 업로드인 경우 Storage 경로 |
| url | 링크인 경우 외부 URL |
| uploaded_by, created_at | 이력 |

### activity_log (변경 이력)

| 컬럼 | 설명 |
|---|---|
| id, table_name, record_id | 대상 |
| action | `insert` / `update` / `delete` |
| diff | 변경 내용 JSON |
| actor_id, created_at | 누가 언제 |

Postgres 트리거로 volume_works, schedules, volumes 변경 시 자동 기록. 홈 화면 활동 피드와 삭제 복원의 근거가 된다.

## 6. 기능 상세

### 6.1 로그인·초대

- 편집부(관리자 역할)가 이메일 주소로 구성원 초대 → 초대받은 사람은 메일의 링크 클릭만으로 로그인.
- 미초대 이메일은 로그인 불가 (members 테이블에 등록된 이메일만 허용).
- 세션 유지로 매번 로그인할 필요 없음.

### 6.2 권별 작품 목록 (핵심)

- 좌측: 기존 literature-db와 동일한 작품 검색(검색어, 교육과정·갈래·작가 필터, 초성 검색).
- 우측: 선택한 권의 수록 목록. 검색 결과에서 클릭 한 번으로 추가.
- 추가된 작품은 `후보` 상태로 시작 → 논의 후 `확정` 또는 `제외`.
- 드래그(또는 위/아래 버튼)로 수록 순서 조정.
- 작품별 메모(선정 이유, 위원 의견).
- **실시간**: 다른 구성원의 추가·변경·순서 조정이 몇 초 안에 내 화면에 반영 (Supabase Realtime 구독).
- 저작권 데이터(기존 copyright.json)와 대조해 작품 옆에 저작권 상태 뱃지 표시.
- 같은 작품이 다른 권에 이미 들어있으면 중복 표시.
- 권별 확정 목록 엑셀(xlsx) 내보내기.

### 6.3 일정

- 시리즈 공통 마일스톤 + 권별 일정(원고 마감, 검토회의, 조판 등).
- 월간 캘린더 뷰와 목록 뷰. 마감 7일 이내 항목은 홈 화면에 강조 표시.
- 완료 체크 가능.

### 6.4 자료실

- 권별 폴더 + 공통 폴더 구조.
- 파일 직접 업로드(HWP, PDF, 이미지 등) 또는 외부 링크(드라이브 등) 첨부 — 등록 시 선택.
- 업로더·등록일 표시, 다운로드, 삭제(이력 기록).
- 업로드 파일 크기 제한 50MB/건 (Supabase 무료 플랜 고려). 초과 시 링크 첨부 안내.

### 6.5 연락처

- 구성원 명부: 이름, 소속, 역할, 담당 권, 전화, 이메일.
- 본인 정보는 본인이 수정 가능, 편집부는 전체 관리.

### 6.6 홈

- 최근 활동 피드 (activity_log 기반): "○○ 선생님이 3권에 「소나기」를 추가했습니다" 형식.
- 다가오는 마감 목록.
- 권별 진행 상태 요약 (권 수, 후보/확정 작품 수).

### 6.7 기존 literature-db 사이트 연동 (선택, 4단계)

- literature-db에 "단행본 수록 현황" 페이지 추가: Supabase의 확정 목록을 읽기 전용으로 표시.
- 공개 범위는 이 시점에 다시 결정 (공개/비공개).

## 7. 오류 처리

- 시트 CSV 로드 실패: 기존 사이트와 동일하게 오류 메시지 + 재시도 버튼.
- Supabase 요청 실패: 저장 실패 시 토스트 알림 + 화면 상태 롤백 (낙관적 업데이트 후 실패 시 복원).
- 실시간 구독 끊김: 자동 재연결, 재연결 시 전체 재조회로 정합성 확보.
- 동시 편집 충돌: 마지막 저장 우선(last-write-wins). 이력이 남으므로 복원 가능. 10명 규모에서는 충분.

## 8. 테스트

- 유닛: 작품 키 생성, 필터 로직(기존 테스트 재사용), 정렬 순서 계산, 활동 피드 문구 생성.
- 컴포넌트: 권 목록 추가/제거/상태 변경 흐름, 파일 등록 폼 (Supabase는 목킹).
- 실배포 전 수동 점검: 2개 브라우저로 실시간 동기화 확인.

## 9. 개발 단계

| 단계 | 내용 |
|---|---|
| 1 (MVP) | 프로젝트 세팅, Supabase 프로젝트·스키마·RLS, 로그인/초대, 권 관리, 권별 작품 목록(검색+추가+상태+순서+실시간) |
| 2 | 일정 관리, 연락처 명부 |
| 3 | 자료실 (업로드 + 링크) |
| 4 | 홈 활동 피드 다듬기, 엑셀 내보내기, 저작권 뱃지, literature-db 수록 현황 페이지 |

각 단계 완료 시점마다 배포하여 실사용 피드백을 받는다.

## 10. 범위 제외 (하지 않는 것)

- 댓글/알림 등 실시간 채팅 기능 (메모 필드로 대체, 필요시 추후)
- 작품 원본 데이터 편집 (시트가 원천, 대시보드는 읽기만)
- 담당 권별 편집 제한 (전원 편집 가능으로 확정)
- 모바일 전용 앱 (반응형 웹으로 대응)
